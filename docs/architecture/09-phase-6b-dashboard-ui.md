# المرحلة 6b: واجهة لوحة التحكم (Next.js) + التحقق الفعلي من الباكيند

> الحالة: منفّذة ومختبرة فعلياً مع الباكيند الحقيقي — 2026-09-26.
> يشمل هذا المستند أيضاً أول تشغيل حقيقي لـ API المرحلة 6a عبر FastAPI و asyncpg، والإصلاحات التي نتجت عنه.

## الهدف

موظف الوكالة يستخدم لوحة عربية (RTL) تعمل على الحاسوب والجوال، ليقوم بالتالي:

- يتابع المحادثات لحظياً، ويستلم أي محادثة من البوت، ويرد، ثم يرجعها للبوت.
- يدير طلبات الحجز: الحالة، والإسناد، والملاحظات، والسجل، والتصدير.
- يدعو زملاءه للفريق.
- يربط قنواته أو يفصلها.

## الصفحات

كل صفحة فيها ثلاث حالات، والنصوص كلها بالعربية:

| الحالة | الشكل |
|---|---|
| التحميل | هيكل رمادي (skeleton) أو مؤشر |
| الفراغ | رسالة تشرح ما سيظهر ومتى |
| الخطأ | رسالة عربية من `lib/api.ts` مع زر «إعادة المحاولة» |

### المحادثات `/inbox`

- القائمة على اليمين والمحادثة على اليسار. على الجوال تظهر واحدة منهما فقط.
- الفلاتر محفوظة في الـ state:
  - `view`: المفتوحة، أو غير المقروءة، أو مع موظف، أو مع البوت، أو المغلقة.
  - الإسناد.
  - القناة.
  - البحث، ويُرسل بعد 350ms من آخر حرف.
- المحادثة المختارة في الرابط `?c=`، فيمكن فتحها برابط مباشر (مثلاً من صفحة الطلبات).
- زر «رجوع» على الجوال يعود للقائمة دون الخروج من اللوحة، حتى لو فُتحت المحادثة من رابط مباشر.
- `Thread` له `key` بمعرّف المحادثة، فلا تنتقل مسودة الرد من محادثة لأخرى.
- «تحميل المزيد» يستخدم `next_cursor`.
- الصفحة تستخدم `Suspense` لأنها تستخدم `useSearchParams`.

### طلبات الحجز `/leads`

- جدول بفلاتر: الحالة، والموظف (`any` أو `unassigned` أو staff id)، والبحث، ومن/إلى تاريخ. مع «مسح الفلاتر» و«تحميل المزيد».
- على الجوال تُخفى الأعمدة الثانوية (`.hide-sm`)، ويبقى: الزبون، والحالة، والتاريخ.
- Drawer التفاصيل فيه:
  - الحالة: تتغير فوراً. اختيار «لم يتم» يُظهر حقل السبب، وزر الحفظ معطّل حتى يُكتب.
  - الإسناد لأي موظف نشط.
  - ملاحظات الطلب.
  - ملاحظة متابعة تُضاف للسجل.
  - سجل مقروء: «غيّر الحالة من «جديد» إلى «تم التواصل»»، «أسند الطلب إلى …».
  - رابط «فتح المحادثة».
- تصدير CSV للمدير فقط: رابط GET عادي بنفس الفلاتر مع `?tenant=`، لأن رابط التنزيل لا يحمل هيدرات.

### الفريق `/team`

- للمدير والمالك. الموظف العادي يرى «هذه الصفحة للمدير فقط»، والـ API يرفض طلباته بـ 403 في كل الأحوال.
- قائمة الأعضاء مع علامة «(أنت)».
- إنشاء دعوة:
  - صلاحية «مدير» تظهر للمالك فقط، مثل قاعدة الباكيند.
  - ملاحظة «لمن الدعوة؟» للتذكير.
- الرابط `${origin}/register?invite=<token>` يظهر مرة واحدة فقط، ومعه:
  - زر نسخ.
  - «مشاركة عبر واتساب» (`wa.me/?text=`).
  - تاريخ انتهاء الرابط.
- قائمة الدعوات بحالاتها: بانتظار القبول، أو تم القبول، أو ملغاة، أو منتهية. مع زر إلغاء بعد تأكيد.

### القنوات `/channels`

- حالة كل قناة، وعلامة «رقم تجريبي»، وآخر فحص، وخطأ الفحص إن وُجد.
  - لا نعرض `last_error` للقنوات المفصولة، لأنه نص تقني داخلي.
- «ربط قناة» يفتح `/connect?tenant=<النشاط الحالي>`، وهي صفحة الباكيند الجاهزة لتدفقات Meta.
- «فصل» بعد تأكيد، للمدير فقط. و«إعادة الربط» للقنوات التي حالتها `needs_reauth`.
- تنبيه إذا لم تبقَ أي قناة مفعّلة.
- الصفحة تُحدَّث عند الرجوع للتبويب (`focus`)، مثلاً بعد إنهاء الربط.
- رسالة ترحيب عند `?welcome=1`، وهي وجهة التسجيل الجديد.

## قرارات التصميم

1. **الحدث إشارة للجلب فقط.**
   - عند وصول `message` أو `conversation` أو `lead` أو `resync` نعيد الجلب من الـ API، بعد تأخير 400–500ms حتى تُجمع الأحداث المتقاربة في طلب واحد.
   - التحديث الصامت يطلب نفس عدد العناصر المحمّلة (حتى 100)، فلا تختفي صفحات حمّلها المستخدم.
   - أي رد أقدم من آخر طلب يُهمل (عدّاد `seq`)، فلا تظهر نتائج فلتر سابق.
2. **فشل التحديث الصامت لا يمسح الشاشة.** إذا فشل تحديث في الخلفية تبقى البيانات المعروضة، ويظهر الانقطاع في مؤشر «متصل لحظياً». شاشة الخطأ للتحميل الأول فقط.
3. **الطلب المفتوح في الـ state وليس في الرابط.** المحادثة وحدها في الرابط (`?c=`)، لأن صفحة الطلبات تشير إليها.
4. **`/connect` يبقى صفحة الباكيند.** تدفقات Meta (Embedded Signup و Facebook Login) جاهزة ومختبرة هناك منذ المرحلة 5، فلم نكرر بناءها.
   - اللوحة تمرر `?tenant=`، والصفحة صارت تختار نفس النشاط.
   - قبل ذلك كانت تختار أول نشاط دائماً، فمالك نشاطين قد يربط رقماً بالنشاط الخطأ.
5. **الجوال:** أعمدة الشبكة `minmax(0, 1fr)` حتى لا توسّع النصوص الطويلة العمود خارج الشاشة، والارتفاع `100dvh`، وأزرار المحادثة في صف مستقل.
6. **البحث بالرقم المحلي (باكيند):**
   - الموظف يكتب `0913334444` أو `091 333 4444` (كما تعرضه اللوحة)، والرقم مخزّن `+218913334444`.
   - `normalize_search` يحوّل النص الذي يشبه رقماً إلى أرقام فقط بدون `00` أو `0` في البداية.
   - الأسماء تبقى كما هي.
7. **بدون مكتبات جديدة للواجهة.** نفس `ui.tsx` و`globals.css` و`lib/*`.
   - تجربة E2E تستخدم Playwright من خارج `package.json` (محلياً أو من التثبيت العام)، فلا يزيد `npm install` ولا يُنزّل متصفحات.
8. **`next-env.d.ts` لا يُرفع بعد البناء.** `next build` يضيف فيه مرجعاً لـ `.next/types`، وهذا يكسر `npm run typecheck` على نسخة جديدة قبل البناء.

- الـ worker حقيقي.
- خادم محلي بديل لـ Meta Graph و OpenAI (`scripts.dev_mock_upstream`).

### تجربة الـ endpoints بـ curl

كلها عبر uvicorn، وبكوكي الجلسة مع `X-Tenant-ID`:

- **الهوية:**
  - التسجيل: 201، والبريد المكرر 409.
  - `/me`.
  - CSRF: POST بدون Origin أو من Origin غريب يُرفض بـ 403.
  - الدخول: كلمة مرور خاطئة 401، والبريد بأحرف كبيرة يعمل.
  - الخروج، ثم الجلسة القديمة ترجع 401.
- **المحادثات:**
  - القائمة والفلاتر والبحث بالعربية.
  - cursor خاطئ 400، و view خاطئ 422، ومحادثة غير موجودة 404.
  - وكالة غريبة 404، وبدون جلسة 401.
  - `read` ثم `takeover`.
  - رد الموظف ثم إعادته بنفس `client_msg_id`، فيرجع `duplicate: true`. والنص الفارغ 422، والحقل الزائد 422.
  - الإرسال الفاشل ثم `retry`، وإعادة رسالة غير فاشلة ترجع 409.
  - البوت لا يرد أثناء الاستلام.
  - `release`: البوت يرد فوراً على رسالة معلّقة (وأنشأ طلب حجز عبر `create_lead`).
  - `assign`: الموظف يسند لغيره 403، ولنفسه ينجح. وعضو غير موجود 422.
  - `close`، ثم `takeover` و`release` والرد كلها 409، ورسالة جديدة من الزبون تفتح محادثة جديدة.
  - نافذة 24 ساعة: `reply_window_closed`.
  - قناة مفصولة: `channel_not_active`.
- **الطلبات:**
  - الفلاتر: الحالة، والإسناد، والبحث، والتواريخ، و`assigned=bogus` يرجع 422.
  - `lost` بدون سبب 422.
  - الحالة مع الإسناد ثم نفس القيم مرة ثانية: لا أحداث جديدة.
  - الملاحظات، وموظف غير موجود 422، وملاحظة من موظف.
  - العودة من «لم يتم» تمسح السبب.
  - السجل باسم الفاعل.
- **التصدير:**
  - BOM، وعناوين عربية، وتوقيت طرابلس، وعلامة LRM قبل الرقم، والفلاتر.
  - الموظف العادي 403.
- **الفريق والقنوات:**
  - الدعوة ثم التسجيل بها، وإعادة استخدامها 404.
  - الإلغاء، والإلغاء المكرر 404.
  - صلاحيات الموظف 403.
  - فصل قناة: الموظف 403، والمالك ينجح.
- **SSE:**
  - الأحداث `ready` ثم `message` و`conversation` و`lead` و`message_status`.
  - لا أسماء ولا أرقام ولا نصوص في الأحداث.
  - يعمل عبر الـ API مباشرة، وعبر rewrites لـ `next start`، وعبر `next dev`. الحدث يصل خلال نحو 0.3 ثانية من الـ webhook.

لم تظهر أي استجابة 5xx في سجلات الـ API.

## التجربة الشاملة محلياً

المتطلبات: Docker و Python 3.11 و Node 20+، ثم Playwright مع Chromium (`npm i -g playwright && npx playwright install chromium`، أو محلياً).

```bash
# الباكيند
cd backend && cp .env.example .env          # عبّئ القيم؛ للتطوير: COOKIE_SECURE=false
#   WEB_ALLOWED_ORIGINS='["http://localhost:3000"]'   و   WHATSAPP_ACCESS_TOKEN=أي-قيمة
docker compose up -d postgres
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
set -a; . ./.env; set +a
.venv/bin/alembic upgrade head
.venv/bin/python -m scripts.dev_mock_upstream 8099 &       # بديل Meta + OpenAI
export META_GRAPH_BASE_URL=http://127.0.0.1:8099 OPENAI_BASE_URL=http://127.0.0.1:8099/v1 OPENAI_API_KEY=sk-mock
.venv/bin/uvicorn app.main:app --port 8000 &
.venv/bin/uvicorn app.admin.main:app --port 8001 &
.venv/bin/python -m app.worker.runner &
# خطة التسجيل الذاتي (مرة واحدة)
.venv/bin/python -m scripts.create_admin --email ops@example.ly --name "مدير" --role superadmin
curl -X POST localhost:8001/admin/plans -H "Authorization: Bearer <adm_...>" -H 'Content-Type: application/json' \
     -d '{"code":"starter","name":"البداية","prices":[{"period_months":1,"price_lyd":"150"}]}'

# الواجهة
cd ../web && npm install && npm run build
cp -r .next/static .next/standalone/.next/static
PORT=3000 node .next/standalone/server.js &                # أو: npm run dev
OWNER_URL=postgresql://app_owner:<pass>@127.0.0.1:5432/agentdb node e2e/dashboard.e2e.js
```

- لقطات الشاشة والملف المصدَّر في `web/e2e/screenshots/`، وهو مجلد مستبعد من git.
- رسالة زبون يدوياً (من `backend/`): `.venv/bin/python -m scripts.dev_send_whatsapp --from 218913334444 --name "أبو محمد" --text "قداش عمرة رمضان؟" --phone-number-id <رقم القناة>`.
- لا تشغّل `npm run dev` في نفس مجلد نسخة `standalone` تعمل، لأنه يعيد كتابة `.next/`.

## القيود والملاحظات

- **لم يُختبر مع Meta و OpenAI الحقيقيين**، فلا يوجد حساب Meta ولا مفتاح هنا.
  - الإرسال والردود مرّت عبر الخادم البديل بنفس العقود (`/{ver}/{id}/messages`، و`chat/completions` مع tools).
  - صفحة `/connect` فُتحت وتم التحقق من اختيار النشاط، لكن Embedded Signup و Facebook Login لم يُشغّلا.
- **ملاحظة متابعة جديدة** (`lead_events`) لا تُرسل NOTIFY، لأن الـ trigger على جدول `leads` فقط. موظف آخر فاتح نفس الطلب يراها عند أي تغيير لاحق في الطلب أو عند إعادة فتحه.
- **التحديث الصامت** يعيد تحميل حتى 100 عنصر، وما بعدها يُحمَّل بـ «تحميل المزيد».
- **Enter يرسل الرسالة** حتى على الجوال، كما في واتساب ويب. Shift+Enter لسطر جديد.
- **حقول التاريخ** تعرض صيغة المتصفح (`mm/dd/yyyy` في بيئة الاختبار)، والقيمة المرسلة `YYYY-MM-DD`.
- **نسخة PostgreSQL:** `CLAUDE.md` يذكر 16، بينما `docker-compose.yml` و`01-architecture.md` يستخدمان 17.
  - الاختبارات هنا على 17 (الـ compose)، وسابقاً كانت على 16 (بدون pgvector).
  - لم نغيّر الـ compose، لأن تغيير الإصدار الرئيسي على قاعدة قائمة يكسر مجلد البيانات. يُستحسن توحيد `CLAUDE.md`.
