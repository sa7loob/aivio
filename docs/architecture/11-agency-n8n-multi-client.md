# 11: التحول إلى وكالة أتمتة (Done For You) على n8n

> وثيقة قرار — 2026-09-26.
> الحالة: البنية التحتية (`agency/`) منفذة ومختبرة محلياً. أول workflow (عميل الحج والعمرة) هو الخطوة التالية.

## القرار

- **توقف العمل على منصة SaaS ذاتية الخدمة** (`backend/` و `web/`). الكود يبقى في المستودع كمرجع ولا يُطوَّر.
- **النموذج الجديد:** الوكالة تجهّز بوت كل عميل وتديره، والعميل يدفع اشتراكاً شهرياً. لا لوحة تحكم للعميل، ولا تسجيل ذاتي، ولا مسودات يراجعها العميل.
- **المحرك:** n8n (self-hosted) لكل سير العمليات. سكربت Python صغير فقط لما لا يناسب n8n، ويعمل كحاوية داخل خلية نفس العميل.
- **السبب** (قرار صاحب المشروع): البيع والتشغيل الآن أهم من منصة كاملة. الوكالة تسلّم أسرع، وتعدّل لكل عميل بدون بناء واجهات.

قواعد `CLAUDE.md` الخاصة بمنصة SaaS تبقى سارية على `backend/` و `web/` فقط إذا عُدّلا.

## 1. العزل: خلية لكل عميل

| | n8n واحد لكل العملاء | **n8n لكل عميل (المختار)** | سيرفر لكل عميل |
|---|---|---|---|
| الـ credentials (توكن واتساب، مفتاح OpenAI) | قاعدة واحدة ومفتاح تشفير واحد. credential خاطئ في workflow = رد من رقم عميل آخر | منفصلة، بمفتاح تشفير خاص | منفصلة |
| سجل التنفيذ (فيه رسائل الزبائن) | مختلط | منفصل | منفصل |
| عطل أو حلقة لا نهائية | يوقف كل العملاء | عميل واحد فقط، بسقف ذاكرة | عميل واحد |
| حذف بيانات عميل | فرز يدوي | حذف قاعدة ومجلد | حذف سيرفر |
| نقل عميل لسيرفر آخر | صعب | نسخة احتياطية + DNS | — |
| الموارد | الأقل | ~350MB لكل عميل | سيرفر كامل لكل عميل |

**الخلية = كل ما يخص عميلاً واحداً:**

```
                    ┌─────────────── VPS (Docker) ───────────────┐
Meta / المتصفح ──► │ Caddy :443  (HTTPS تلقائي لكل نطاق)         │
                    │   hajj.bots.example.ly ──► n8n-hajj ──┐     │
                    │   shop.bots.example.ly ──► n8n-shop ──┤     │
                    │                                        ▼     │
                    │   Postgres: قاعدة hajj (مستخدم hajj فقط)     │
                    │             قاعدة shop (مستخدم shop فقط)     │
                    └─────────────────────────────────────────────┘
```

| منفصل لكل عميل | مشترك |
|---|---|
| حاوية n8n وسقف ذاكرتها (`N8N_MEM_LIMIT`) | السيرفر |
| قاعدة بيانات ومستخدم Postgres لا يدخل غيرها (ولا قاعدة `postgres`) | Caddy |
| مفتاح التشفير `N8N_ENCRYPTION_KEY` | عملية Postgres |
| مجلد الملفات `data/n8n/<اسم>` | شبكة Docker |
| النطاق الفرعي وشهادته، وحساب n8n | |
| الـ credentials: تطبيق Meta، الرقم، مفتاح OpenAI | |

**التحصين المطبّق** (في `docker-compose.yml` و `Caddyfile`):

- **من الإنترنت:** المنفذان 80 و443 فقط. Postgres و n8n بدون منافذ خارجية.
- **الوصول:**
  - مسارات `/webhook/*` فقط مفتوحة للإنترنت.
  - المحرر وواجهة `/rest` خلف كلمة مرور Caddy، ثم دخول n8n الخاص بالعميل.
- **داخل n8n:**
  - الـ workflows لا تقرأ متغيرات البيئة (`N8N_BLOCK_ENV_ACCESS_IN_NODE`).
  - الحزم المجتمعية معطلة.
- **البيانات:**
  - سجل التنفيذ يُحذف بعد 14 يوماً (`EXECUTIONS_MAX_AGE_HOURS`).
  - الملفات (الصوت) على القرص وليس في الذاكرة.

**مخاطر مقبولة** (موثقة):

- **الشبكة المشتركة:** كل الحاويات على نفس شبكة Docker، فـ workflow يستطيع مخاطبة n8n عميل آخر داخلياً. لكن الوكالة وحدها تكتب الـ workflows، ونسخة العميل الآخر تطلب دخوله الخاص.
- **أسماء القواعد** ظاهرة لكل مستخدمي Postgres (`pg_database`)، أما محتواها فلا.
- **نقطة عطل مشتركة:** سقوط Postgres أو السيرفر يوقف الكل. الحماية: النسخ الاحتياطي الليلي، ونقل العميل الكبير لسيرفر آخر عند الحاجة.

## 2. داخل كل عميل: تنظيم الـ workflows

**نفس القالب لكل العملاء، والإعدادات تختلف.** البيانات في قاعدة العميل، وليست مكتوبة داخل الـ workflows:

```
[WA] Inbound        ← Webhook: GET (تحقق Meta) + POST (الرسائل)
  ├─ التحقق من X-Hub-Signature-256 بـ App Secret العميل، ثم رد 200 فوراً
  ├─ تجاهل التكرار (message.id) وتحديثات الحالة (statuses)
  ├─ رسالة صوتية؟ ← تنزيل الوسائط ← تفريغ (لغة ar + تلميحات بأسماء الباقات والمدن الليبية)
  └─► [Agent] Reply
[Agent] Reply       ← آخر الرسائل + الباقات من قاعدة العميل ← OpenAI ← {reply, lead}
  ├─ إرسال الرد عبر WhatsApp Cloud API وحفظه في السجل
  └─ طلب حجز مكتمل؟ ─► [Lead] Notify
[Lead] Notify       ← حفظ في جدول leads + تنبيه واتساب لهاتف صاحب الشركة
[System] Errors     ← Error Workflow: أي فشل يصل للوكالة فوراً
```

**قواعد التنظيم:**

- **البيانات في قاعدة العميل** (schema `public`؛ جداول n8n الداخلية في schema `n8n`):
  - `packages` (الباقات والأسعار)، `faq`، `settings` (هاتف المالك، ساعات العمل)، `leads`، سجل المحادثات.
  - تحديث الأسعار = تحديث جدول، وليس تعديل workflow.
- **التسمية:**
  - الـ workflows: `[WA]` و `[Agent]` و `[Lead]` و `[System]`.
  - الـ credentials: `<عميل> · WhatsApp` و `<عميل> · OpenAI` و `<عميل> · DB`.
- **القوالب في git:**
  - تُصدَّر الـ workflows بدون credentials إلى `agency/workflows/`.
  - عميل جديد = استيراد القوالب، وربط credentials العميل، وتعبئة جداوله.
  - هذه القوالب هي منتج الوكالة.

**Meta:** تطبيق Meta لكل عميل داخل حساب أعمال العميل نفسه. العميل يملك الرقم والحساب، والوكالة مضافة كمسؤول.

- رابط الـ webhook واحد لكل تطبيق، فيشير لنطاق العميل مباشرة (`https://hajj.bots.example.ly/webhook/...`).
- التوقيع يُتحقق منه بـ App Secret الخاص بالعميل.
- تطبيق يستخدم أصول مالكه فقط لا يحتاج عادةً مراجعة تطبيق (App Review). تحقّق من ذلك عند إعداد أول عميل.
- التوكن: System User token دائم لكل عميل.
- العميل الذي يغادر يأخذ أصوله دون أن يتأثر غيره.

**OpenAI:** مشروع (Project) لكل عميل بمفتاح وسقف إنفاق خاصين.

- التكلفة الشهرية لكل عميل واضحة للتسعير.
- عميل واحد لا يستنفد رصيد الباقين.

**الوكيل (قرار مقترح للـ workflow الأول):** استدعاء OpenAI مباشر، مع كل الباقات داخل الـ system prompt ومخرجات JSON منظمة `{reply, lead}`، بدل عقدة AI Agent مع أدوات.

- كتالوج وكالة حج صغير يتسع في الـ prompt. الأسعار تأتي من الجدول حرفياً، بدون بحث قد يخطئ.
- استدعاء واحد لكل رد: تكلفة وزمن متوقعان.
- عقدة AI Agent في n8n مبنية داخلياً على LangChain، وقاعدة المشروع السابقة تمنعه.

**تنبيه المالك:**

- رسالة واتساب لصاحب الشركة خارج نافذة 24 ساعة تحتاج **قالباً معتمداً** من نوع Utility (مثل `new_lead`). جهّزه مبكراً، لأن الاعتماد يأخذ وقتاً.
- داخل النافذة تكفي رسالة عادية.

**الاحتفاظ بالبيانات:** سجل التنفيذ 14 يوماً. مدة سجل المحادثات في قاعدة العميل تُحدَّد في عقده (مثلاً 90 يوماً).

## 3. ما نعيد استخدامه من المشروع السابق

- **الـ system prompt باللهجة الليبية وقواعد الرد:** `backend/app/agent/prompts.py`.
- **تلميحات التفريغ** (مدن ليبية، مصطلحات الحج والعمرة): `LIBYAN_TERMS` و `build_transcription_prompt` في `backend/app/ai/transcription.py`.
- **استخراج الباقات من بروشور العميل** (schema و prompt): `backend/app/ai/catalog.py`. مفيد للوكالة لإدخال كتالوج عميل جديد بسرعة.
- **دروس مختبرة:**
  - انتظر التفريغ قبل الرد.
  - لا سعر يقوله البوت قبل مراجعة بشرية (هنا: مراجعة الوكالة).
  - تجاهل تكرار الرسائل بمعرّف Meta.

## 4. ما تم التحقق منه فعلياً (محلياً)

الإصدارات: n8n 2.40.7، و Caddy 2.11.4، و Postgres 17 (pgvector)، و Docker 29، و Compose 5.1. استُخدمت نطاقات `*.localhost` بشهادات Caddy الداخلية بدل Let's Encrypt.

| الاختبار | النتيجة |
|---|---|
| `docker compose up` ثم `new-client.sh` لثلاثة عملاء (hajj، shop، clinic) | كل الحاويات healthy، ونحو 8 ثوانٍ لكل عميل |
| المحرر بدون كلمة مرور Caddy، أو بكلمة خاطئة، أو `/rest` | 401 |
| المحرر بكلمة المرور | 200، وإنشاء حساب n8n عبر HTTPS ناجح |
| المتصفح (Chromium) خلف كلمة مرور Caddy | الدخول يعمل، واتصال `/rest/push` (WebSocket) مفتوح، بدون رسالة «connection lost» |
| workflow بـ webhook منشور | `POST /webhook/ping` بدون كلمة مرور = 200. نفس المسار على عميل آخر = 404. التنفيذ مسجّل في قاعدة hajj فقط |
| HTTP | تحويل 308 إلى HTTPS |
| عزل Postgres | مستخدم hajj لا يدخل قاعدة shop ولا قاعدة `postgres`، ويستطيع إنشاء جداول في قاعدته. مفاتيح التشفير مختلفة |
| حماية السكربت | اسم عميل موجود أو اسم غير صالح: رفض |
| `backup.sh` ثم `pg_restore` لقاعدة hajj في قاعدة مؤقتة | workflow واحد، وتنفيذ واحد، وحساب المالك: كلها موجودة |
| إعادة كاملة من الصفر بالملفات النهائية | ناجحة، والـ healthcheck (`/healthz/readiness`) أصبح healthy |

**مشاكل اكتُشفت في التجربة وأُصلحت قبل الرفع:**

- n8n 2.40.7 يعتبر Postgres 16 خارج النطاق المدعوم ويطلب 17 أو أحدث، فانتقلنا إلى `pgvector/pgvector:pg17`.
- n8n يستمع على `::` افتراضياً، ويتوقف إذا كان IPv6 معطلاً، فأضفنا `N8N_LISTEN_ADDRESS=0.0.0.0`.
- الإعداد `WEBHOOK_URL` صار قديماً (deprecated) في n8n 2.x، واستُخدم `N8N_WEBHOOK_URL`.
- مستخدم العميل كان يستطيع الاتصال بقاعدة `postgres` الافتراضية، فأُضيف `REVOKE CONNECT`.

**لم يُختبر:**

- Let's Encrypt الحقيقي على نطاق عام.
- اتصال n8n بـ Meta و OpenAI. بيئة الاختبار تمرّ عبر proxy بشهادة خاصة، فأي اتصال خارجي من داخل الحاويات فشل هنا.
- **يجب التأكد منهما على الـ VPS.**

## 5. الخطوة التالية: أول workflow (عميل الحج والعمرة)

المطلوب من العميل أو الوكالة قبل البناء:

1. تطبيق Meta ورقم واتساب (رقم الاختبار يكفي للبداية)، و App Secret، و System User token.
2. مفتاح OpenAI (مشروع خاص بالعميل).
3. قائمة الباقات: الاسم، التواريخ، أسعار رباعي وثلاثي وثنائي بالدينار، وما يشمله السعر.
4. رقم هاتف صاحب الشركة للتنبيهات.
